# Showing the flagship Crew

Open the public site and scroll to Meet the team behind the possibilities, or choose Meet our Crew. Select a role and Meet. Introductions start fresh unless the visitor explicitly checks Share my recent text. Use Your role, Show an example and For my business. Each role is prepared guidance, not a connected back-office system.

For a coordinated demonstration, ask Autumn to meet the billing specialist, review June's offered identity, choose whether to share context and Continue. The server requires the offered target; visitors cannot select another business or inherit a prospect's knowledge. Choose Request a consultation to reach the form. Sending requires separate visitor consent; an inquiry is not a booking. New conversation returns to Autumn and clears shared text.

All six provider configurations exist; live website voice/callback/transfer remains unavailable. Do not promise appointment confirmation, invoice access, payments, CRM changes or support ticket delivery. Use the inquiry form for actual owner-reviewed requests. Do not request passwords or payment details.

Registry changes: edit `website-receptionist/src/crew-routing.mjs`, validate facts and permissions, build and test. Cards and options generate from that registry. Provider prompts are exported by `node website-receptionist/scripts/provision-flagship.mjs`; re-review before any provider mutation. Existing public IDs prevent duplicate creation. Use the secure setup runbook; keep credentials and private numbers outside Git.

Validation: `npm test` and `npm run build` in website-receptionist; `npm test` in owner-ops. Browser script/evidence in `docs/qa/flagship-six/`. Hosted publication uses the Sites supported source/package workflow and existing public project; never overwrite private demo identity or reuse consumed grants.
